## Internal representation

`packages/world-model/index.ts` defines strict versioned `ProjectWorldModel`, `ObservedFact`, `DerivedObservation`, grounded support, temporal relationship, token link, perception binding, query, and view schemas. Every bounded collection has a maximum; set-like collections require unique canonical order. The world ID is `contentId("world_snapshot_v1", body)` over every body field, including `asOf`, scope, parent, authorization, coverage, change set, provenance, and exact references. Its own ID is excluded. Exact parent publication resolves caller-supplied parent artifact bytes through `EditorialArtifactMap`; semantic world identity and exact-byte artifact SHA remain distinct. Snapshot and view outputs are recursively frozen.

Core records hold references and small declarations, not media, vectors, masks, transcript blobs, provider responses, credentials, model weights, renderer projects, or executable commands. There is no database or persistence service. A supplied `EditorialArtifactMap` resolves only explicit caller-provided artifacts and verifies exact bytes. Populated snapshot construction and view validation require that map. Coverage state must match an exact `WorldCoverageEvidence` artifact with the same scope, source-analysis inventory, channel declarations and producer provenance; an arbitrary pointer cannot certify completeness.

`ObservedFact` binds project, creator, purpose, a source-grounded subject, observation type, `Availability<EvidenceRef>` value, non-empty evidence, producer, computation-key availability, uncertainty, and content identity. Interpretive types such as camera motion and aesthetic score are rejected as observed facts. `DerivedObservation` binds its own content identity, actual producer, dependencies, interpretation type, value availability, uncertainty, and explicit conflicts. All derived dependencies are checked, must be acyclic, and must terminate at grounded observed evidence. Creative hypotheses have no representation in the factual/derived snapshot. Conflicting derivations remain separate records.

Source support binds exact `FootageAnalysis` artifact, asset ID, source hash, shot, range pointer, and PTS pointer. A supplied range must equal the referenced analysis range and remain within its shot. Optional frame support checks sample ID, frame index, time, hash, source PTS, and half-open interval membership. Observation/derivation payload references must belong to their source analysis or an exact authorized Gate-1 binding. The snapshot checks original `FootageAnalysis` authorization for every source scope. Same-source temporal relations are checked against those intervals; cross-snapshot alignment requires a supplied `ClockMap` artifact whose endpoints, units, and error bound agree exactly. No global clock or narrative order is inferred.

## Legacy token and Gate 1 joins

The adapter reads an exact supplied `EditorialToken` artifact and calls existing `validateTokenEvidence`. It links token ID, exact token artifact, candidate, FootageAnalysis, FootageRun, and source authorization. Supplied candidate sets are validated against their exact token links. Creator scope comes from validated FootageAnalysis authorization because the token has no creator field. The adapter neither creates nor mutates a token. Distinct token snapshots for one candidate remain distinct; all five future channels stay missing-only, and accepted half-open locality remains intact.

Gate 1 output is joined only through an explicitly supplied reuse receipt, computation identity, source support, and source authorization. Validation checks exact project, creator, purpose, key, selected output type/version, attempt and selection reference types, source size, and range/frame/sample timebase identity. The receipt alone does not establish a source join. There is no fabricated `PerceptionArtifactIndex` snapshot and no enumeration of `PerceptionEvidenceStore` internals. Historical perception bindings are not a claim of permanently eligible reuse; a later reuse still needs Gate 1's own scoped lookup.

## Publication, invalidation, and views

Pure publication returns a new revision with an exact parent reference and supplied acyclic lineage. It retains historical observation references and checks exhaustive additions, unchanged references, superseded roots, and the deterministic transitive invalidation closure. Invalidated records stay in history, while current views omit their entities and report missing dependencies. A failed publication has no parent mutation or partial output.

Every view query binds the exact world ID, scope, purpose, current source authorization, explicitly supplied current `MediaAsset` references and access time, query version, authority categories, channels, optional exact filters, offset, and a hard result limit of 256. Current `MediaAsset` scope, expiry and deletion status are checked separately from the historical world authorization; denied access returns a generic unavailable error. The query ID binds the exact request. The view ID binds the world ID, returned references, authority tags, coverage, missing channels/dependencies, omissions, and next offset. `complete_for_bound` only describes the declared query bound and supplied coverage; `bounded` reports omitted matches; `partial` reports missing channels/dependencies or unspecified channels. None means nothing else exists in the project.
