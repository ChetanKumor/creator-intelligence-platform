# Reference evaluation protocol 1

`packages/evaluation/reference.ts` provides a separate boundary benchmark; the frozen Phase 0 ranking benchmark is unchanged. A benchmark has an ID/version/freeze time, one or more content-addressed cases, creator grouping, source duration and rational fps, annotator ID, label source, ordered internal cut timestamps, and a digest of the frozen cases. Ground truth is either generated synthetic boundaries or manually reviewed authorized media. Predictions are stored separately.

Use `contentId("benchmark", cases)` to freeze the cases digest. `verifyReferenceBenchmark` rejects tampering, duplicate asset identities, invalid timings or oversized tolerances. The CLI joins the benchmark to the analyzed SHA-256, verifies matching duration/fps, and requires the local-evaluation authorization purpose. Only safe manifests may be committed; references remain in ignored local directories. No benchmark media is automatically acquired.

The default demonstrated protocol uses **±1 frame**: tolerance seconds equals `toleranceFrames * fps.denominator / fps.numerator`. The manifest allows only one or two frames. Report the tolerance alongside every result. The FPS defines the nominal frame tolerance; VFR labels are actual PTS and require manual review of whether this nominal tolerance is appropriate. It is not a universal VFR frame-accuracy claim. The 1-microsecond domain continuity tolerance is a separate arithmetic invariant, never the detector evaluation tolerance.

Boundary matching is ordered, earliest feasible, one-to-one within tolerance. This maximizes match count for ordered boundaries and does not let multiple predictions claim one label. Precision = TP/(TP+FP); recall = TP/(TP+FN); F1 = 2TP/(2TP+FP+FN). Empty denominators yield null, while missed labeled cuts yield F1 zero. Timing error is absolute error over the reported matched pairs (mean and maximum); unmatched boundaries remain FP/FN, not hidden timing observations. The start and terminal media boundaries are excluded.

The analyzer always reports schema-valid count/rate for the analyzed input, wall-clock runtime per source minute, sampled-frame count, and embedding cache hit rate. Without a supplied benchmark, boundary metrics remain null with a missing-evidence reason. No semantic accuracy or embedding quality is reported without the necessary ground truth/task. Opening, middle and ending statistics are equal-time thirds with internal cut counts/density, not hook/build/reveal labels.

Determinism checks compare shot partitions, sample PTS/indices, IDs and embedding references for repeated identical inputs/configuration. Operational timestamps, runtime, cache counters and run IDs are expected to change. Float normalization tests use numerical tolerance. Aggregate comparisons across detector/model candidates must preserve the benchmark version/digest, configuration and runtime evidence; neither detector nor model size is declared universally superior.

The integration suite generates a 3-second vertical reference with two known cuts, tests both detectors, repeats analysis to verify cache reuse, and separately tests 0.2-second shots, rotation, VFR and corrupt/unsupported media. Synthetic F1 verifies plumbing on these controlled cases; it establishes no general Reel-boundary accuracy. The Python suite exercises installed SigLIP processor/forward APIs with tiny generated parameters and mocked loading, plus missing-cache and GPU-fallback behavior. That is distinct from a pretrained-model smoke test.
